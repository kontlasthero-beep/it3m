# Second Chance Adventure Editor

Open `http://localhost:4177/editor.html` while the local game server is running. The editor is intentionally unavailable on the deployed server. Browser drafts are saved locally with IndexedDB; export a JSON file to share or back up a stage.

The local editor also discovers image files in `World_illustration`, `Card_illustration`, `영웅 초상화`, `in-game-screen/curling-table-maps`, and `in-game-screen/game-objects`. New files appear in the palette while the editor is open (within about 10 seconds, or when the window regains focus). Choosing one imports it into the current stage so saved drafts and exported JSON remain self-contained. Files in `in-game-screen/game-objects/beacons` and `in-game-screen/game-objects/wires` appear under the dedicated **비콘** and **전선** categories, which also accept uploaded images. `game-objects/fake-wall` and `game-objects/moving-walls` are classified under **구조물**; their initial placement sizes match the game's gavel and moving-rail footprints. The moving-walls category includes the static **매설 레일** decoration and the separate **프레임 이동 구조물**. AAB humanoid concepts in `World_illustration` appear under portraits. The five exploration-mark PNGs in `adventure/reward-icons` are bundled **기타 이미지** assets, visible even when `editor.html` is opened as a local file. They can be imported to a stage background, placed as decoration objects, or selected by scene illustration actions. Their exported asset records reference their packaged paths, so the game art folder must travel with such an export. The discovery endpoint is local-only. Beacon and wire categories have gameplay handlers; images in other categories need a specific runtime handler for new mechanics.

## Stage package

An exported `second-chance-adventure-stage` JSON file embeds uploaded PNG, JPEG, WebP, MP3, WAV and OGG files as base64 data URLs in `assets`. Existing game art is referenced by `builtin:` IDs. The five packaged exploration-mark images use validated relative `src` paths instead of base64; keep the `adventure/reward-icons` directory with the game when sharing a stage that uses them. Importing a file creates a separate draft and never overwrites an existing one. Beacon, routed floor wire and powered-structure settings are preserved in `objects[].runtime` and evaluated in the playable adventure stage.

| Field | Purpose |
| --- | --- |
| `format`, `version`, `id` | File identity and schema version |
| `title`, `subtitle`, `briefing`, `designerNotes` | Stage presentation and production notes |
| `mapId`, `backgroundAssetId`, `fallBounds` | Existing map or uploaded full-canvas background, plus this stage's fall rectangle |
| `objective` | Proposed clear condition, target, turn limit, extra rules |
| `explorationMarks` | Stage completion marks: `iconSet` (`beacon` default or `wayfinder`) and up to two `bonus` conditions |
| `loadout.startingHand` | Candidate cards, initial card count and ordered/random selection |
| `loadout.deck` | Bag cards in draw order, or shuffled when random |
| `objects` | Placed stones, structures, triggers, art, zones and note markers; `groupId`, `flipX`, `flipY`, `visible` and supported `runtime` fields persist editor transforms and mechanics |
| `objects[].notes` | Visual direction and placement intent |
| `objects[].mechanicNotes` | Exceptional collision, effects, timing or other rules to implement |
| `dialogue` | Intro, success, failure or event lines with numeric priority, portrait and voice asset references; each line can store `presentation` for typography, reveal, typing sound and production direction |
| `variables`, `events` | Stage-local values and ordered condition/action rules authored in the scene workbench |
| `assets` | Uploaded media with a `category` (`stone`, `structure`, `trigger`, `card`, `portrait`, `map`, `decoration`, or `audio`) |

Coordinates use the live game's 1200 × 772 canvas. New and older stages start with the standard fall boundary `x=88..1112`, `y=68..662`. Object positions are center coordinates. Brick and data-barrier defaults use 18 × 64; stone defaults use 58 × 58. The editor reproduces the current map image crop and marks the chosen fall boundary separately.

Selecting an object shows a bounding box with eight handles. Corners preserve the original aspect ratio; top, bottom, left and right handles change only one dimension. The opposite corner or side stays fixed, including for rotated objects. The grid toggle also snaps resize dimensions; the inspector still accepts exact dimensions. The stone, structure and trigger palettes each include a gray `D` dummy for planning new units. Dummies are editor placeholders; Stage 01 gives selected dummies stage-specific runtime behavior documented in `adventure/EDITOR_HANDOFF.md`.

The small round handle above the top-right corner rotates a selected object. Hold Shift (or Ctrl) and click objects to select several; the common handle rotates that selection around its center. Grouping keeps them selected and makes a click on any member select the whole group for moving or rotating. The group can be split again with **Ungroup**. The inspector's horizontal and vertical flip buttons work on one object or a selection. Group, rotation, and flip values survive save, export, and import. Older files without these fields open with ungrouped, unflipped objects.

Choose an upload category before adding images, or change an uploaded image's category below its palette entry. Audio is classified automatically. Categories organize the palette and choose the initial kind for newly placed objects; changing an uploaded image's category does not silently change already placed objects' collision kind. The stage panel's **Upload map image** button adds PNG/JPEG/WebP art and applies the latest image as the full 1200 × 772 background. Clicking an uploaded map entry applies it as the background. Existing exported backgrounds without a category are migrated to `map` when imported.

Use **Boundary edit** on the board to drag a fall edge or corner until it matches the visible map edge. The four numeric fields in the stage panel allow exact coordinates; **Default** restores the standard rectangle. Bounds cannot leave the canvas or shrink below 80 × 80. Changes support undo/redo and persist in drafts and exported JSON. Local/online matches retain their original boundary; playable Adventure Stage 01 consumes its exported `fallBounds`.

An export is a design specification, not executable gameplay. New mechanics described in `mechanicNotes` require implementation and playtesting in the game. The objective type is a proposed rule; a stage runtime must validate it before awarding completion or rewards. Keep original exported JSON files alongside any later converted runtime stage data.

## Exploration marks

The **탐사 표식** controls in the stage panel select an icon pair and up to two extra conditions. Clearing awards one mark. Each satisfied extra condition awards one more, for a maximum of three. `hand-card` checks whether the chosen card ID remains in the player's hand when the stage clears; `trigger-count` checks how many distinct triggers the player collected. `variable` lets the designer write a condition description and select a stage variable, comparison operator and expected value. The written sentence is displayed as an icon tooltip, while the variable comparison determines whether the mark is awarded. Define the variable and its event-driven updates in **연출**; an unconnected variable condition awards no bonus. Failure awards zero. Stage 01 uses the B beacon icons by default, with Reposition remaining in hand and collecting both triggers as its two extra conditions. The A wayfinder pair is another complete icon set; the C route seal remains available in **기타 이미지** as a standalone concept. A stage JSON export retains the `explorationMarks` settings.

The stage selection and clear result show earned and broken icons. The best result for a signed-in account is currently saved in that browser's local storage; guest progress lasts only for the current page session. Server-side account synchronization and rewards based on mark totals have not yet been implemented.

## Scene rules and mechanic controls

The **연출** workbench stores rules in `events`. Each rule selects a game trigger, optional variable conditions, and ordered actions. Supported triggers and actions are listed in `adventure-event-catalog.js`, which both the editor and game use. Current actions can present dialogue or an uploaded illustration, shake the screen, play uploaded audio, show or hide a placed object, and change a stage variable. Show/hide also changes collision for physical objects; decorations do not collide. Stage 01 JSON without `events` or `variables` remains valid.

The object inspector reads `mechanics` from the same catalogue. Numeric and toggle controls change `objects[].runtime`, which is preserved through export/import and consumed by gameplay. Current configurable physics cover the dummy stone pulse and the reposition trigger. Any exceptional rule that exists only as prose still needs implementation before it will work in play. Newly discovered image files can be imported as art; adding a new interactive unit requires a runtime handler and a catalogue entry.

For placed blue and red stones, the **스톤 · 충돌 상태** controls set `objects[].runtime.fixed` and `objects[].runtime.neutralizeOnCollision`. A fixed stone stays at its placed coordinates despite impacts and cannot be repositioned. An armed stone turns neutral on its next collision with a stone, bullet, or structure. These values survive export/import and are used by the playable stage. The **추적** and **무력화** card illustrations are discoverable in `Card_illustration`; both card IDs are accepted in stage loadouts.

Place one **압력 비콘** from the 비콘 category and configure its condition checkboxes in 개체. With no conditions, **조건이 없을 때 활성** selects its steady state. With one or more conditions, **그리고** requires all selected conditions and **또는** requires at least one. A stone must stop on the beacon; a structure overlaps it; a connected wire supplies incoming power; a release pulse activates the pulse condition for the rest of that stage attempt. A beacon can turn off when its stone, structure or incoming power condition ceases. The same object switches its off/on appearance automatically. A wire from the 전선 category has a single route: drag its endpoints or bends on the board, double-click a segment to add a bend, or use the inspector buttons. Endpoints snap within 12 board units of another endpoint, beacon center or power-reactive structure center. Wire crossings and middle bends do not connect. Set each item's input, output or both port mode in 개체. Wires stay flat and non-colliding; power-reactive structures show a powered glow and can drive **전력 활성화/비활성화** events in 연출. The large 대사 미리보기 in 연출 edits and previews explicit line breaks, font, reveal and typing speed.

For every new gameplay mechanic or presentation action, update the runtime behavior, shared catalogue, editor controls, and round-trip/gameplay tests together. Add art/audio to the local discovery directories above so the editor can find it. Update this file and `adventure/EDITOR_HANDOFF.md` with new fields and bindings. This keeps future stage edits in one JSON format and makes new behaviors available for later stages.

The stage panel has separate card lists for the starting hand and player bag. Use each section's card picker and add button; add the same card more than once for multiple copies, then use the arrow buttons to set order. Every starting-hand candidate is also in the bag, including duplicate copies. Adding one to the hand automatically adds a missing copy to the bag; the bag cannot remove a copy still required by the hand. Older exports with separate lists are reconciled on import. In ordered mode the starting hand takes the first `drawCount` candidates; in random mode it samples that many without replacement. Selected starting cards are removed from the bag once, while unselected candidates remain there. The remaining bag independently preserves its listed draw order or shuffles once at stage start. Export/import and browser drafts retain both modes and all card IDs. Older stages without a `loadout` retain the original one-card reposition starting hand. The current playable adventure is a single-turn stage: its starting hand is active, while later bag draws need a multi-turn stage runtime.

Dialogue priority starts at 1; lower numbers play first. New lines append after existing lines. In the dialogue tab, select a line and use the arrow buttons or its priority field to reorder it. Priorities are renumbered without gaps, persist through export/import, and legacy stages without priorities retain their original insertion order. `dialogueForCue(stage, cue)` returns the nonblank lines for a situation in priority order. The editor preview uses that same function; the future adventure runtime can consume it when the matching situation occurs.

The dialogue text box keeps Enter line breaks in the game and editor preview. Each line's **글꼴**, **글자 크기**, **등장 효과**, **타자 속도**, **타자 효과음**, and **연출 메모** controls are saved in `dialogue[].presentation`. The font choices include the existing default/serif/mono values and five bundled local Korean fonts: IBM Plex Sans KR, Noto Sans KR, Gowun Batang, Black Han Sans and Do Hyeon. See `fonts/README.md` for sources, licenses and suggested uses. Reveal choices are instant, typewriter and fade. Select an uploaded audio clip for typing ticks. **이 대사 미리보기** follows the game's dialogue width (620px, or 500px with the result title for success/failure); the side preview also replays the selected effect. The production direction is saved for the designer and is not displayed to players. The game skips motion when the browser requests reduced motion. Existing lines without `presentation` keep the original instant text behavior.
