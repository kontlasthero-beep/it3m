# Second Chance · Expedition UI Kit v1

게임의 실제 UI 요소를 조사해 만든 디자인 시안입니다. `salvage`의 버튼 아트와 색·테두리 체계가 `index.html`에서 불러오는 `game-ui-kit.css`를 통해 로컬 게임에 적용되었습니다. `signal`과 아직 연결되지 않은 HUD 파일은 비교·후속 작업용으로 남겨 두었습니다. 브라우저에서 [review.html](review.html)을 열어 디자인 계열·상태·큰 화면/작은 화면을 바꿔 보세요.

## 디자인 계열

| ID | 이름 | 의도 | 우선 검토 화면 |
| --- | --- | --- | --- |
| `salvage` | Salvage Terminal | 탐사대가 회수해 쓰는 무광 금속 장비. 어두운 판과 절제된 황동, 청록 표시등. | 로비, 카드, 인게임 HUD |
| `signal` | AAB Signal | AAB가 남긴 유선형 신호 장치. 얇고 선명한 청록 회로와 어두운 면. | 모험 모드, 기믹, 온라인 상태 |

`game-lobby-screen/button-concepts/source-moodboards/`의 두 PNG는 형태 탐색용 이미지입니다. 실제 UI 후보는 여기서 다시 그린 SVG입니다. 무드보드의 가짜 문자나 과한 장식은 UI 파일에 넣지 않았습니다.

## 범위와 용도

`manifest.json`이 각 요소의 **용도, 실제 화면의 CSS 선택자, 크기, 버튼의 글자 안전 영역, 모든 파일 경로**를 담은 기준 목록입니다. `kit-spec.cjs`는 생성용 원본 목록입니다.

| 화면·기능 | 버튼 | HUD·창 |
| --- | --- | --- |
| 계정 | 로그인, 등록, 게스트, 닉네임 변경, 로그아웃 | 입력창, 접속 상태 |
| 로비 | 게임 시작, 튜토리얼, 도감, 덱 만들기, 계정 설정 | 닉네임·계정 정보, 명성치·레벨 |
| 플레이 방식 | 공개 방, 코드 참가, 로컬 2인, 온라인 방, AI, 모험 | AI 초상화, 영웅·맵 선택 |
| 온라인 | 새로고침, 참가, 방 만들기 | 방 목록 행, 코드 입력, 접속 상태 |
| 인게임 | 설정, 턴 종료, 발사, 파워 결정 | 양쪽 점수와 내역, 매치·맵 정보, 타이머, 남은 스톤, 속도, 턴 정보, 트리거, 가방, 파워 미터 |
| 카드·덱 | 저장, 초기화 | 기본/선택/잠금 카드 테두리, 카드 상세·획득 알림, 내 차례/상대 차례 손패, 덱 빌더·프리셋 |
| 모험·서사 | 스테이지 이동·플레이 | 스테이지 선택·잠금·목표, 빅보이 대화창, 모험 대화창, 탐사 표식 보상·상태, 튜토리얼 단계 |
| 도감·설정·결과 | 뒤로가기 | 도감, 탭, 설명 말풍선, 설정창·볼륨 레버, 승패 결과, 해금 알림·로딩 |

현재 목록은 **버튼 30종, HUD·창 46종, 아이콘 23종**입니다. 버튼에는 2개 계열 × 큰/작은 화면 × 기본/hover/누름/비활성 상태가 있습니다. HUD에는 2개 계열 × 큰/작은 화면 버전이 있습니다. 모든 SVG에 같은 이름의 PNG·WebP를 2배 해상도로 제공합니다. `status: proposed`인 일부 알림은 게임에 아직 없는 사용 제안입니다.

## 파일 구조

```text
expedition-ui-kit-v1/
  buttons/{salvage,signal}/{id}--{desktop,compact}--{idle,hover,pressed,disabled}.{svg,png,webp}
  modules/{salvage,signal}/{id}--{desktop,compact}.{svg,png,webp}
  icons/{name}.{svg,png,webp}
  manifest.json
  review.html
  review-data.js
  kit-spec.cjs
  generate-assets.cjs
```

예: `buttons/salvage/home-play--desktop--idle.svg`는 로비의 ‘게임 시작’ 버튼 기본형입니다. `modules/signal/turn-timer--compact.svg`는 좁은 화면용 타이머 배경입니다. 모든 PNG·WebP는 해당 SVG의 2배 픽셀 크기로 내보냈습니다.

## 적용을 검토할 때

1. **텍스트는 이미지에 넣지 않습니다.** HTML의 실제 글자를 이미지 위에 배치해야 닉네임·점수·번역·접근성·반응형 글자 크기가 유지됩니다. 미리보기 페이지의 글자는 시안 위에 얹힌 HTML 예시입니다.
2. **한 장의 래스터 이미지를 임의의 폭으로 늘리지 않습니다.** SVG를 현재 슬롯의 비율에 맞게 사용하거나, 모서리를 보존하는 `border-image`/9-slice와 별도 중심면을 사용합니다. 지금 SVG는 명시된 `desktop`·`compact` 슬롯 비율에 맞춘 후보이며, 모든 중간 폭을 무손실로 커버하는 9-slice 산출물은 아닙니다.
3. **선택 영역은 장식보다 넓게 둡니다.** 현재 설정 버튼은 실제로 약 34×34px, 턴 종료는 높이 30px 안팎입니다. 작은 화면에서는 시각 크기와 별도로 44×44px 정도의 클릭 영역을 확보해야 합니다.
4. **가변 이름을 시험합니다.** 로비의 긴 닉네임·계정 ID, AI 이름, 카드 이름, 공개 방 제목과 모바일 2열 메뉴의 ‘방 코드 입력하기’가 위험 지점입니다. 줄임표·2줄 허용·글자 축소의 우선순위를 화면별로 정해야 합니다.
5. **중요한 정보는 색만으로 구별하지 않습니다.** 선택과 잠금은 선/형태·자물쇠·문구를 동반해야 하고, 타이머 경고는 숫자를 계속 보여야 합니다. `disabled`와 `hover` 파일은 디자인 방향이며 실제 `:focus-visible`, 키보드·터치 입력 검증이 필요합니다.
6. **카드 그림과 프레임은 분리합니다.** 카드 프레임에는 삽화나 효과 문장을 굽지 않았습니다. 74×100px 안팎의 현재 손패 카드와 232×340px 도감 확대판에 같은 세부 프레임을 그대로 축소 적용하면 글자·선이 지나치게 작아집니다. 작은 카드용 프레임을 별도 선택해야 합니다.
7. **게임 판의 판정선은 UI로 가리지 않습니다.** 카드 칸·점수판·도구창이 테이블 가장자리에 겹치는 실제 레이아웃을 고려해야 합니다. 이 에셋은 맵과 충돌판정을 바꾸지 않습니다.

## 재생성

Node.js와 `sharp`가 있는 환경에서 `node generate-assets.cjs`를 실행합니다. `sharp`가 별도 경로에 있으면 `SHARP_MODULE` 환경변수에 모듈 경로를 지정합니다. 원본 SVG, 2배 PNG·WebP, `manifest.json`, `review-data.js`를 다시 만듭니다. 기존 게임 UI에는 자동 적용되지 않습니다.

## 현 상태

로비 버튼은 해당 SVG를 배경으로 사용하고, 나머지 공통 창·카드·게임 HUD는 같은 색과 재질을 CSS로 재구성했습니다. 텍스트는 `SecondChance Gowun Batang`을 우선 사용하며 좁은 카드 이름·숫자는 기존 산세리프를 사용합니다. 명성치 총량은 로비 기본 표기에서 숨기고 바에 마우스를 올리거나 키보드로 초점을 맞추면 다음 레벨까지 필요한 양을 보여줍니다. 미리보기용 `signal`과 미연결 HUD는 실제 게임에 아직 적용되지 않았습니다.
