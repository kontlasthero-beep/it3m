# Second Chance Repository Notes

When the user says **에디터 이식 패키지**, create or update an editor handoff for gameplay assets and mechanics added since the previous package. Follow `adventure/EDITOR_HANDOFF.md`: provide a machine-readable JSON manifest and a concise Markdown note with asset paths, configurable mechanics, object and dialogue bindings, assumptions, and verification. Do not deploy or edit the separate editor project unless the user asks.

When implementing a new Adventure game mechanic, physics parameter, event trigger, presentation action, or usable asset, update the local Adventure Editor in the same task. Register editable fields and labels in `adventure-event-catalog.js`, preserve them in `adventure-editor-model.js`, connect them in `adventure-runtime.js`/`index.html`, and expose them in `editor.js` if the catalogue alone does not cover them. Keep new image/audio files in the discovery directories documented in `ADVENTURE_EDITOR.md`. Add a round-trip test for the stage JSON and a gameplay test for the behavior. Update `ADVENTURE_EDITOR.md` and `adventure/EDITOR_HANDOFF.md` when the authoring contract changes. A design note in `mechanicNotes` is not an implemented mechanic.
