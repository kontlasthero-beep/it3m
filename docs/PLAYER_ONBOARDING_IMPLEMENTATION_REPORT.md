# Second Chance — 신규 플레이어 유입·입문 개선 구현 보고서

작성일: 2026-11-08  
분석 기준: 현재 게임 코드와 사용자가 전달한 ‘직관적이지 않다’는 피드백  
문서 상태: 구현 제안. 아래 신규 시스템은 아직 게임에 적용하지 않았다.

## 1. 판단과 목표

카드 설명을 줄이고, 추천 덱과 카드 시험모드를 제공하며, 발사를 당김 조작으로 통합하는 방향은 타당하다. 현재 플레이어는 게임의 목표를 이해하는 동시에 파워 결정, 방향 지정, 카드 대상, 충전 후 발동, 영웅과 덱 구성까지 배워야 한다. 이러한 판단을 처음부터 한꺼번에 요구하는 흐름을 줄이는 것이 핵심이다.

다만 튜토리얼의 **범위**와 첫 접속 시 반드시 거쳐야 하는 **길이**는 구분해야 한다. 시스템 전반을 다루는 학습 기능은 확장하되, 첫 플레이 전에 모든 내용을 통과하게 만들면 진입 과정이 더 길어진다. 기본 조작은 짧게 배우고, 심화 기능은 필요해지는 순간에 선택적으로 배우는 구조를 권한다.

이번 계획은 신규 방문자가 실제 플레이어로 전환되는 비율과 이후 재방문을 높이는 데 직접 기여한다. 처음 사이트를 발견하는 사람의 수를 늘리는 일은 별도의 유입 경로가 필요하다. 따라서 ‘들어오는 사람을 늘리는 작업’과 ‘들어온 사람이 쉽게 시작하는 작업’을 함께 측정해야 한다. 현재 어떤 단계에서 가장 많이 이탈하는지는 아직 계측 결과가 없으므로, 아래 진단은 코드 구조와 전달된 피드백에 근거한 가설이다.

**권장 경험 순서**

접속 → 짧은 조작 실습 → 준비된 덱으로 첫 판 → 궁금한 카드 시험 → 추천 덱 일부 수정 → 자신의 덱 구성 → 심화 규칙·수집·세계관 탐색

## 3. 사용자 계획의 구체화

### 3.1 카드·영웅 능력 설명 간략화

한 카드가 처음 보여줄 정보는 ‘대상 → 일어나는 일 → 다음 행동’이다. 모든 카드를 같은 글자 수로 맞추기보다, 효과를 이해하는 데 필요한 조건과 불이익을 남긴다. 일반적인 카드는 1~2문장, 운명·묘기처럼 핵심 조건이 여러 개인 카드는 그보다 길어질 수 있다.

| 정보 단계 | 출력 위치 | 담을 내용 |
| --- | --- | --- |
| 핵심 효과 | 카드 앞면, 손패 확인 | 대상과 주요 결과. 중요한 제한·불이익 포함 |
| 조작 안내 | 카드를 선택하거나 끌기 시작할 때 | ‘내 스톤에 놓기’, ‘판에 놓기’, ‘대상을 당겨 놓기’ 중 필요한 안내 |
| 상세 규칙 | 카드 상세창·용어 설명·도감 | 중첩, 지속시간, 구조물 파괴, 예외, 정확한 수치 |
| 기록 | 도감 | 기존 방침에 따른 세계관·이야기 |

예시 초안이며, 실제 변경 전에 현재 모든 판정과 대조해야 한다.

| 카드 | 짧은 설명 초안 | 별도로 바로 접근할 수 있어야 하는 정보 |
| --- | --- | --- |
| 경질화 | 내 스톤의 마찰력을 2배로 높입니다. 중첩할 수 있습니다. | 중첩 계산, 정제본 3배, 발사 전에 쓰면 이동 거리 감소 |
| 방출 | 내 스톤을 충전합니다. 충돌하면 주변을 밀어내는 파동을 냅니다. | 아군 밀침 절반, 구조물 파괴, 총알과의 상호작용 |
| 총알 장전 | 내 스톤에 총알을 장전합니다. 스톤을 당겼다 놓아 발사하세요. | 발사 기회 미소모, 총알 속도 고정, 정제본 부채꼴 조절 |
| 데이터 장벽 | 내 스톤만 통과하는 장벽을 놓습니다. 다음 상대 턴이 끝나면 사라집니다. | 총알로 파괴 가능, 정제본 영구 유지 |
| 분석 | 이번 게임에서 사용된 카드 하나를 골라 정제된 상태로 가져옵니다. | 분석 제외, 운명 이동 예외, 정제본+일반본 획득 |
| 도구 교체 | 손패와 가방에서 한 장씩 골라 교체하고, 두 카드를 정제합니다. | 사용 카드 선택 제외, 이미 정제된 카드 재강화 없음 |

운명처럼 상대에게 이동하며 손패를 봉쇄하는 카드는 핵심 제한을 숨기면 안 된다. 정제된 묘기처럼 결과가 바뀌는 카드도 ‘효과 강화’라는 표현만으로 처리하지 않는다. 카드 시험으로 실제 결과를 확인할 수 있게 한다.

‘마찰력’은 ‘더 잘 멈추고 덜 미끄러지는 정도’, ‘중립’은 ‘거리·추락 점수를 주지 않으며 양쪽이 아군 대상으로 카드를 쓸 수 있는 스톤’처럼 짧은 용어 풀이를 제공한다. 중립 스톤에 탈출을 사용하면 점수를 얻는 예외는 상세 설명에 남긴다.

구현 시 `CARD_DESCRIPTIONS`, `LEARNING_DETAILS`, 정제 레지스트리의 서로 다른 문장이 어긋나지 않도록 공통 설명 메타데이터를 둔다. 대상·핵심 효과·조작·키워드·상세 규칙·시험 장면 ID를 연결하고, 실제 판정에는 설명 문장을 파싱해 사용하지 않는다. 수치는 가능한 경우 기존 밸런스 값에서 읽는다. 명칭은 명조체, 효과 본문은 현재 방침대로 가독성 높은 본문 글꼴을 유지한다.

### 3.2 튜토리얼을 시스템 전반으로 확장

**기본 과정**은 첫 실행에서 안내하되, 건너뛰기·재시도·설정 접근을 유지한다. 아래 시간은 실측 전 설계 목표다.

| 기본 실습 | 수행할 행동 | 성공 기준 |
| --- | --- | --- |
| 1. 배치와 발사 | 높이를 고르고, 당겨서 지정한 넓은 영역에 멈춘다 | 힘과 방향 조작을 한 번 성공. 처음부터 정확히 80점 강요하지 않음 |
| 2. 점수와 위험 | 점수 방향·추락 경계를 확인하고 상대를 밀어낸다 | 어느 쪽이 고득점인지 이해하고 충돌 한 번 성공 |
| 3. 카드와 턴 | 카드 한 장을 쓰고 필요하면 추가 조작 후 턴을 끝낸다 | 대상 선택, 카드 사용, 턴 종료를 수행 |

목표 길이는 약 2~4분이다. 빅보이는 화자로 유지하되 짧은 대사 뒤 실제 조작을 배치한다. 처음에는 넓은 성공 범위를 주고, 정밀한 80점 실습은 선택 심화 과정으로 옮긴다. 장면을 불러온 뒤 대사·투하·조작 가능 상태가 순서대로 이어지는 기존 연출도 보존한다.

**확장 학습**은 기존 튜토리얼 메뉴에서 각각 고를 수 있고, 기능을 처음 만날 때 해당 실습만 제안한다.

| 개별 실습 | 학습 범위 | 자연스러운 진입 시점 |
| --- | --- | --- |
| 점수 자세히 보기 | 거리 점수·내 턴 낙사 보너스·영웅별 예외 | 첫 결과 화면 또는 점수 도움말 |
| 발사형 카드 | 총알 장전·해방·묵직한 한방·정제 블랙홀·재배치 | 해당 카드를 처음 사용할 때 |
| 카드 대상 | 아군·상대·중립·판·구조물 대상 | 카드 상세창의 시험 기능 |
| 트리거 | 설치·습득·직전 사용 제한·추가 충전 | 트리거 도구 첫 사용 |
| 정제 | 가공기와 3회 사용, 조작이 변하는 카드 | 리파이너 첫 선택 |
| 상태 | 중립·고정·충전·방어 중첩·디버프 | 해당 상태 첫 확인 |
| 덱 만들기 | 8장, 한 종류만 2장, 영웅 제한 | 첫 덱 편집 |
| 카드 회수·교체 | 분석, 도구 교체, 가방 고갈 | 해당 카드 시험 |
| 특수 맵 | 구조물 레일, 아이템, 얼음판, 결투 점수 방향 | 처음 그 맵에 입장할 때 |

모든 학습을 강제 팝업으로 띄우지 않는다. 기본적으로 짧은 안내와 ‘연습해 보기’를 제공하고, 온라인 경기 중에는 다른 플레이어의 흐름을 멈추지 않는다. 온라인에서 긴 설명을 여는 경우 실습은 경기 종료 후로 연결한다.

튜토리얼 진행 여부는 기존 `tutorialCompleted` 하나로 전부 처리하지 않는다. 기존 재배치·모험 해금과 보상 수령 기록은 유지하고, 새 실습은 별도 ID·버전·완료 여부로 기록한다. 튜토리얼 개편 때문에 기존 이용자를 강제로 처음부터 다시 진행시키거나, 이미 받은 보상이 반복 출력되어서는 안 된다. 게스트의 해당 기기 학습 상태와 계정의 영구 학습 상태도 구분한다.

### 3.3 추천 덱

초기 구현은 검수된 덱 템플릿으로 충분하다. 외부 AI API나 대규모 승률 학습 없이도 작은 카드 풀에 맞는 추천이 가능하다. 추천은 ‘가장 강한 덱’보다 ‘사용법이 이해되는 덱’부터 제공한다.

- 처음에는 안정형·공격형·정제형 등 소수의 차이가 분명한 선택지만 노출한다.
- 각 덱에는 영웅, 8장 구성, 플레이 방법 한 문장, 대표 카드 2~3장, 간단한 연계 예시를 둔다.
- ‘이 덱으로 사용’은 이번 플레이 선택에 반영한다. 기존 저장 덱을 자동 덮어쓰지 않는다.
- ‘내 덱으로 저장’은 비어 있는 슬롯에 복사한다. 슬롯이 가득 차면 교체할 슬롯을 이용자가 고른다.
- 잠긴 카드를 포함하는 덱은 실제 게임에 불법 카드가 들어가지 않도록, 보유 카드로 합법적인 대체 구성을 다시 검증한다. 무엇이 바뀌었는지 보여준다.
- 편집 중에는 ‘남은 카드 채우기’를 제공하되 이용자가 이미 넣은 카드를 보존한다. 가능한 합법 구성이 없으면 정확한 이유를 알린다.

입문용 예시: 빅보이 + 경질화 2장 / 방호벽 / 총알 장전 / 방출 / 구조물 투하 / 블랙홀 방출 / 재배치. 정확히 8장이며 중복은 경질화 한 종류뿐이다. 안정적인 정지와 단순한 밀침을 경험하도록 만든 학습용 초안이다. 재배치 미해금 상태라면 사용 가능한 대체 카드로 구성하고, 실제 추천 여부는 플레이 검수 후 확정한다. 현재 카드 풀에서는 추천 덱이라도 처음부터 8장을 채우려면 일정 수준의 학습 복잡도가 남는다.

추천 데이터에는 `templateId`, `heroId`, `cardIds`, `replacementPriority`, `difficulty`, `planSummary`, `balanceVersion`, `trialScenarioIds`를 둔다. 카드의 내부 역할 태그를 활용하되 카드 타일에 카테고리 문구를 다시 표시하지 않는다. 영웅 제한, 해금, 8장, 한 종류만 2장 규칙은 클라이언트와 `deck-config` 서버 검증을 함께 통과해야 한다. 임시 전체 제공 카드가 회수되어도 추천 덱이 재검증되어야 한다.

### 3.4 카드 시험모드

카드마다 실제 게임 엔진을 사용하는 짧은 실습 장면을 준비한다. 카드 상세창에서 ‘시험하기’를 누르면 적절한 스톤·장애물·카드가 배치된 연습판으로 들어간다. 사용하지 못하는 카드를 시험할 수 있게 하더라도 그 사실이 계정의 보유 상태를 바꾸어서는 안 된다.

필수 기능은 장면 초기화, 다시 시도, 일반/정제 비교, 원래 화면으로 복귀다. 처음에는 전후 상태를 비교하고 핵심 효과를 한 번 사용해 보는 정도로 만든다. 사용법이 다른 정제본은 별도 장면이나 입력 단계를 가진다.

| 카드 그룹 | 시험 장면 |
| --- | --- |
| 경질화·반발장 | 같은 입력으로 시전 전후 밀림·정지 차이 비교 |
| 방출·블랙홀 | 여러 스톤과 가벽이 있는 장면에서 범위·발동 조건 확인 |
| 총알·해방·묵직한 한방 | 이미 발사된 내 스톤에 사용하고, 당김으로 발동 |
| 데이터 장벽 | 아군은 통과하고 상대는 부딪히는 장면 |
| 추적·무력화 | 표식과 충돌 이후 결과, 중립·고정 차이 확인 |
| 운명·묘기 | 카드 봉쇄·중립화와 원본/분신의 서로 다른 피격 결과 |
| 분석·도구 교체 | 시험 세션 안에 지정된 사용 기록·손패·가방을 제공 |

시험판은 실제 대전의 스톤·효과·충돌·카드 사용 함수를 호출한다. 별도의 간이 물리로 비슷하게 흉내 내면 ‘연습에서 본 결과와 실전 결과가 다르다’는 문제가 생긴다. 장면 재현에는 고정된 초기 배치와 난수 시드를 사용한다.

실제 경기 중의 상태를 연습판으로 덮어쓰지 않는다. 시험은 독립된 세션으로 실행하거나 현재 경기가 없는 화면에서만 진입한다. 대전 보상·전적·경험치 API를 호출하지 않고, 가방·손패·분석 사용 기록도 시험 세션에 격리한다. 종료 시 해당 세션의 타이머·입력·선택창·효과음·워커 요청을 해제한다. 분석이 이전 판 기록을 가져오던 문제와 같은 상태 누출을 예방하는 기준이다.

## 4. 발사 버튼 제거와 당김 조작 개편

### 4.1 일반 발사 흐름

현재 ‘높이 배치 → 발사 버튼 → 파워 미터 → 방향 드래그’에서 ‘높이 배치 → 당겨서 놓기’로 바꾼다. 배치 직후에는 스톤을 조금 크게 투하하는 현재 연출을 유지하고, 착지한 다음 별도의 새 입력으로 조준한다. 배치를 확정한 클릭의 손을 떼는 동작이 발사로 이어지지 않도록 입력을 분리한다.

1. 투명한 배치 스톤은 기존 x축에 고정하고 y축만 지정한다.
2. 배치 확정과 착지가 끝나면 스톤을 잡을 수 있다.
3. 당긴 반대 방향으로 조준선이 나타난다. 당긴 정도에 따라 파워가 증가한다.
4. 손을 놓으면 발사한다. 아주 짧은 당김은 취소하고 발사 기회를 소모하지 않는다.
5. Esc·우클릭·터치 취소 등으로 실제 발사 전 조준을 취소할 수 있다.

파워 계산의 초안은 `power = clamp((pullDistance - deadZone) / (maxPull - deadZone), 0, 1)`이다. 당김 길이의 기준 좌표와 화면상의 표시 길이를 명확히 나누어, 창 크기나 브라우저 배율에 따라 동일한 의도의 입력이 다른 힘이 되지 않게 한다. 기존 실제 최대 발사 속도·영웅 보정·마찰·충돌 계수는 그대로 사용하면서 입력만 교체하는 것으로 시작한다. 파워 곡선을 비선형으로 바꾸는 밸런스 조정은 별도 비교 후 결정한다.

현재 설정의 `maxPullDistance`는 275이고 방향 전용 거리는 96이다. 기존 숫자를 화면상의 당김 거리로 그대로 재사용하면 작은 화면과 양 끝 발사 위치에서 손이 화면 밖으로 나갈 수 있다. 기본 당김 감도는 실제 화면에서 조정하고, 포인터 캡처·안전 여백·취소 처리와 함께 검수한다. 휴대폰에서는 손가락에 가려지지 않는 위치에 파워 표시를 띄운다. 키보드로 각도·파워를 조절하고 확인하는 대체 입력은 후속 접근성 항목으로 설계한다.

### 4.2 특수 발사는 같은 조작, 서로 다른 값

| 행동 | 당김으로 결정하는 것 | 유지해야 할 판정 |
| --- | --- | --- |
| 일반 발사·일반 재배치·지원군 발사 | 방향과 파워 | 기존 스톤·중립·발사 기회 규칙 |
| 정제된 재배치 | 사전 선택한 파워에 방향만 지정 | 30/50/70/100% 선택 유지 |
| 일반 총알 장전 | 방향 | 현재처럼 최대 총알 속도 고정 |
| 정제된 총알 장전 | 방향과 부채꼴 확산각 | 총알 속도 고정, 70% 당김에서 최대 확산각 |
| 해방 | 방향 | 일반 스톤 50% 발사에 준하는 기존 트리거 운동량 |
| 묵직한 한방 | 충격파 방향 | 카드의 기존 위력·범위, 기본 발사 기회 미소모 |
| 정제 블랙홀 방출 | 끌어올 부채꼴 방향 | 해당 카드의 범위·채널링·유체화 규칙 |

각 기능이 일반 발사와 똑같이 파워를 변경한다고 오해하지 않도록 조준 중 필요한 정보만 표시한다. 완전한 충돌 결과나 최종 정지점을 자동 예측하는 선은 우선 넣지 않는다. 짧은 방향선·파워와 카드에 필요한 범위만 보여주어 판단의 재미를 유지한다.

### 4.3 온라인·AI·튜토리얼 동시 수정 범위

- `needsPowerMeter`, 파워 시작/확정, 드래그 제한, `launchCurrentUnit`, 조준 미리보기와 입력 처리 전반을 함께 바꾼다. 버튼만 숨기는 수정으로 끝낼 수 없다.
- 온라인은 손을 놓은 시점의 방향·파워를 호스트가 검증하고 적용한다. UI 입력을 호스트의 현재 최대 속도·카드 상태·소유권·턴 범위에서 재검증한다.
- 결투 맵의 좌우 플레이어 모두 동일한 조작 감도를 갖게 한다. 중립 스톤의 조작자는 카드 시전자라는 기존 재배치 판정을 보존한다.
- AI는 이미 수치로 고른 방향·파워를 발사 요청에 전달하고, 파워 미터를 기다리는 실행 단계를 제거한다. 탐색 결과와 실제 발사가 다른 값을 쓰지 않도록 공통 변환 함수를 둔다.
- 연습·모험·리플레이용 초기 상태와 에디터의 발사 안내가 새 입력 방식에 맞아야 한다. 모험 스테이지의 기존 고정 파워 설정은 호환 처리한다.
- 기존 40초 턴 시간은 우선 유지한다. 입력 단계가 줄었다는 이유만으로 시간까지 동시에 줄이지 않고, 실제 플레이 데이터를 본다.

## 6. 화면별 사용 흐름

### 처음 접속한 플레이어

기존 게스트 진입 → 짧은 기본 실습 또는 건너뛰기 → 사용법이 명확한 추천 덱 선택 → 준비된 일반 맵 연습 경기 → 결과 → ‘같은 덱으로 다시’ 또는 카드 확인.

회원가입과 자신의 덱 제작을 첫 판의 선행 조건으로 추가하지 않는다. 계정 생성은 저장할 진척이 생겼을 때 기존 경고·저장 안내와 연결한다. 게스트 기록이 실제 계정으로 자동 이전되는지는 별도 구현 범위로 다루며, 구현 전에는 저장된다고 표시하지 않는다.

### 처음 덱을 만드는 플레이어

덱 보관함 → 새 덱 → 영웅 선택 → 추천 덱으로 시작 또는 직접 구성 → 8장 상태 상시 확인 → 카드 상세·시험 → 저장.

추천 덱에서 출발해도 일반 편집과 같은 데이터·검증·저장 애니메이션을 사용한다. 일반본·정제본을 시험한 사실이 실제 덱에 정제 카드를 영구 저장한다는 의미가 되어서는 안 된다.

### 카드가 궁금한 플레이어

도감 또는 편집 카드 상세 → 핵심 효과 확인 → 필요하면 용어 풀이 → 시험하기 → 직접 시전·리셋·정제본 비교 → 원래 카드와 화면 위치로 복귀.

| 모험 런타임·에디터 | 실제 새 연출·목표·입력 설정이 생길 때 편집 가능 항목도 등록 |

핵심 세션 데이터의 초안:

```js
{
  mode: 'match' | 'tutorial' | 'card-trial',
  sessionId: '...',
  roundId: '...',
  globalTurn: 0,
  onboardingVersion: 1,
  activeLessonId: null,
  pendingSelection: {
    sessionId: '...', roundId: '...', turn: 0,
    owner: 0, sourceCardInstanceId: '...'
  }
}
```

선택창·입력·콜백은 소유한 세션·판·턴이 끝나면 무효화한다. 실습 완료 기록과 단순한 창 열람 기록은 분리한다. 명성치·전적·카드 해금은 서버가 실제 경기·완료 조건으로 검증하며 클라이언트의 연습 모드 플래그만으로 보상을 결정하지 않는다.

`index.html` 전체를 먼저 다시 작성할 필요는 없다. 설명·입력 변환·장면 데이터처럼 경계가 명확한 부분부터 파일로 분리하고, 실제 카드·충돌 함수는 공통으로 호출하는 방식이 현실적이다.

## 8. 구현 순서와 완료 기준

| 단계 | 범위 | 선행 작업 | 완료 기준 |
| --- | --- | --- | --- |
| A | 현재 진입 흐름 측정, 설명 규칙·메타데이터 정리 | 없음 | 카드별 대상·조작·상세 규칙 목록과 이벤트 정의 합의 |
| B | 당김 발사 통합, 다음 행동·대상 표시 | A의 입력 규칙 | 양쪽 발사·일반/재배치/특수 카드·온라인·AI의 실제 결과 일치 |
| C | 카드 시험모드 공통 틀과 대표 카드 | A, B | 경질화·총알·방출·무력화·분석 등 서로 다른 유형 시험, 상태 누출 없음 |
| D | 짧은 기본 튜토리얼과 필요할 때 여는 실습 | B, C | 새 이용자가 점수·조작·카드 사용을 수행, 기존 보상 중복 없음 |
| E | 추천 덱과 나머지 채우기 | A, C | 보유/해금/영웅 제한과 8장·중복 규칙 준수, 저장 덱 무단 덮어쓰기 없음 |
| F | 전체 카드·영웅·맵 심화 실습 확장 | C~E | 모든 특수 사용법을 시험·도움말로 찾아갈 수 있음 |
| G | 유입 경로 연결과 측정 기반 수정 | 기본 과정 안정화 | 같은 유입 집단의 첫 발사·첫 판 완료·재방문 변화 비교 |

B를 먼저 하는 이유는 앞으로의 실습을 새 조작 기준으로 만들기 위해서다. C는 카드별로 중복된 튜토리얼을 새로 만들지 않게 해 주며, D와 E는 이 공통 틀 위에서 일부 병행할 수 있다.

첫 배포 단위는 A+B와 가장 짧은 기본 발사 안내로 묶는다. 두 번째는 대표 카드 시험+C+D, 세 번째는 추천 덱과 심화 학습으로 나누면 원인 파악이 쉽다. 물리 밸런스까지 동시에 바꾸지 않아야 조작 개선의 영향을 판단할 수 있다.

## 9. 필요한 에셋과 UI 제작 범위

- 기존의 질감 있는 구리 프레임·낮은 채도의 패널, 영웅 초상화, 카드 삽화를 우선 재사용한다.
- 새로 필요한 핵심 에셋은 당김 길이/방향 표시, 유효 대상·취소 상태, 짧은 점수 방향 표시, 상태 아이콘, 시험판 초기화 표시다.
- 텍스트를 이미지에 구워 넣지 않고, 에셋의 안전 영역 안에 실제 텍스트를 배치한다. 긴 카드명·정제 접두어·다른 화면 폭을 고려한다.
- 카드 카테고리는 내부 필터 데이터로 사용하고 타일마다 반복 노출하지 않는다.
- 추천 덱의 영웅과 카드 설명은 ‘왜 이 덱을 쓰는지’가 먼저 읽혀야 한다. 장식·슬로건·설정상의 문구를 불필요하게 추가하지 않는다.
- 튜토리얼 음성은 기존 대사 ID와 `voiceSrc` 확장 방식을 유지한다. 짧은 조작 시연은 실제 엔진 재생으로 우선 제작한다.
- 테스트 폭은 최소 360px의 좁은 화면부터 데스크톱까지 포함하고, 브라우저 확대·모션 감소·터치 입력을 함께 확인한다.

## 11. 유입·정착 지표

| 지표 | 계산/관찰 방법 | 알아낼 수 있는 문제 |
| --- | --- | --- |
| 첫 발사 도달률 | 신규 방문 세션 중 첫 정상 발사 세션 비율 | 로그인·대사·입력 장벽 |
| 첫 발사까지 걸린 시간 | 방문부터 첫 발사까지, 성공 세션의 중앙값 | 과도한 진입 단계 |
| 기본 학습 완료·건너뛰기 | 완료/스킵/중단을 각각 집계 | 강제 학습의 부담 |
| 첫 판 완료율 | 첫 판 시작자 중 결과 화면 도달 비율 | 실전 이해·게임 길이 |
| 잘못된 카드 사용 시도 | 사용 불가 이유별 횟수, 카드별 구분 | 대상·타이밍·용어 오해 |
| 추천 덱 사용 후 첫 판 | 추천 선택→시작→완료 흐름 | 선택이 실제 플레이로 연결되는지 |
| 시험 후 사용 | 카드 시험 후 같은 카드의 실제 사용 흐름 | 시험모드의 학습 효과 |
| 다음 날 재방문 | 정의된 신규 집단의 익일 재방문 | 첫 경험 뒤 지속 관심 |

이벤트 초안은 `session_open`, `lesson_start/complete/skip`, `stone_launch`, `card_rejected(reason)`, `trial_start/end`, `recommendation_selected`, `deck_saved`, `game_complete` 정도로 제한한다. 최초 방문 판별은 기기·계정 기준을 명시하고, 비로그인 방문을 정확한 개인 수로 단정하지 않는다. 닉네임·비밀번호·폼 입력 내용이나 전체 마우스 궤적을 이 목적의 이벤트에 넣을 필요는 없다. 이벤트 수집 범위와 보관 정책은 실제 적용 시 기존 개인정보 안내와 일치시킨다.

첫 발사까지 90초 이내, 기본 과정 약 2~4분은 **초기 설계 목표**이며 달성 사실이 아니다. 전환율·재방문율의 개선 목표는 기존 값을 먼저 측정한 후 정한다.

유입 경로는 우선 기존 웹 포스터와 실제 게임 링크를 연결하고, ‘짧은 조작을 바로 경험할 수 있다’는 사실을 영상·이미지로 보여준다. 이후 필요하면 특정 연습 과제·추천 덱을 여는 공유 링크를 추가한다. 방 초대 링크에는 코드 정도만 전달하고 로그인 토큰·비밀번호를 넣지 않는다. 유입용 공유 기능은 기본 입문 흐름이 안정된 다음에 진행한다.
